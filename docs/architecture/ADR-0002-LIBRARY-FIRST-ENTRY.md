# ADR-0002：以唱片库作为默认产品入口

- 状态：Accepted
- 日期：2026-08-16
- 适用版本：COCEAN v1
- 替代范围：`COCEAN_V1_IMPLEMENTATION_CONTRACT.md` 7.2、7.3、11.2、11.3 中关于默认入口、一级导航与 Album 信息层级的历史定义

## 决策

登录后的默认产品入口统一为 `/library`。根路由、品牌入口、已登录状态下的
`/login`、旧 `/today`、`/discover`、`/find` 链接以及未知前端路由，都直接以
replace 方式进入 `/library`，不经过旧页面或二次跳转。

桌面与移动一级导航只保留唱片库、任务、我的系统和设置。设置继续位于桌面侧栏
底部。`/quarantine` 作为受保护的兼容深链保留，但不再出现在一级导航或快捷入口。
Home、Discover、Quarantine 页面以及 recommendations、lifecycle API 均不删除。

## 原因

COCEAN 的首要用户任务是管理本地唱片。让推荐、找歌和内部隔离机制占据默认入口，
会弱化本地唱片管理平台的定位，也会造成桌面与移动导航不一致。直接落到唱片库可
减少导航成本，同时保留旧链接和既有恢复合同，避免入口收敛演变为数据或权限变更。

## 约束

- 兼容路由必须直接 replace 到 `/library`，不得闪现旧内容、形成循环或保留伪造的
  查询状态；
- Album 详情继续先呈现用户内容，资料、版本和生命周期管理默认折叠；
- 空唱片库只提供现有真实能力：扫描 Music 目录或添加实体唱片；
- 关键窄屏导航、选择和管理操作保持至少 44px，并提供可见键盘焦点；
- 本决策不改变鉴权、生命周期、任务、文件操作或 API 数据合同。

## 历史关系

冻结的 `COCEAN_V1_IMPLEMENTATION_CONTRACT.md` 保留原文，不做静默改写。本 ADR
对其中以下意图形成后续、局部替代：

- 7.2 的 `/today`、`/find` 页面入口定义：页面与 recommendations API 保留，但旧
  前端入口只兼容跳转到 `/library`；
- 7.3 的 Album Detail 信息层级：继续满足既有读模型，同时将管理证据默认折叠在
  用户内容之后；
- 11.2 的 Desktop Sidebar：用唱片库、任务、我的系统、设置替代“今日、唱片库、
  找歌、我的系统、任务”的一级组合；
- 11.3 的导航文字约束：不再显示“找歌”，但继续遵守设置位于桌面侧栏底部、NAS
  状态保持低层辅助信息的约束。

除以上入口、导航和信息披露顺序外，本 ADR 不替代 7.2 的 API 合同，不改变鉴权、
角色权限、生命周期账本、任务数据、文件操作或 `/quarantine` 深链权限。
