# Epic 3 Context: Library First 管理入口

<!-- Compiled from planning artifacts. Edit freely. Regenerate with compile-epic-context if planning docs change. -->

## Goal

让登录用户打开 COCEAN、点击品牌标识或进入兼容路由时都直接到达唱片库，并将一级导航收敛为真正可用的核心管理入口；同时把底层“隔离”机制转译为可从真实任务和生命周期结果访问的“最近删除”，确保导航简化不会牺牲查询、审计、恢复、安全边界或角色权限。

## Stories

- Story 3.1: 以唱片库作为产品默认入口
- Story 3.2: 从任务记录管理“最近删除”

## Requirements & Constraints

- `/`、未知前端路由和品牌入口必须进入 `/library`；既有 `/today`、`/discover`、`/find` 链接只做无循环、无 404、无权限绕过的兼容重定向，不再渲染旧页面。
- 桌面与移动一级导航只保留唱片库、任务、我的系统和设置；桌面设置继续固定在侧栏底部。今日、找歌、隔离区及未实现能力不得残留在菜单、快捷入口、禁用按钮或空页面中。
- 最近删除不作为一级模块。存在真实生命周期记录时，管理员可从任务页或操作结果进入对应记录，查看真实数量、最近状态、对象、文件数、空间、时间、失败原因和恢复后果；空状态不得用演示数据、模板时间线或“空成功”伪装能力。
- 现有恢复流程必须保持预览、明确确认、幂等执行、审计、可恢复和失败关闭；永久删除继续关闭，本 Epic 不扩展到曲目级删除。
- ADMIN 可按既有合同执行恢复；MEMBER 仅能查看允许的概要；匿名用户不得获得 actor、绝对路径、完整历史证据或管理动作。API、日志、报告和 UI 都不得泄露敏感路径或内部标识。
- 列表及路由变更必须保持既有查询、筛选、分页、稳定排序、SSR、浏览器返回和滚动恢复契约。故障必须展示真实状态及可操作原因。
- 窄屏保持单列可用，关键触控目标至少 44px；桌面与窄屏均须有页面级渲染和可访问性回归，并覆盖 ADMIN、MEMBER、匿名、直接路由、空状态和错误状态，不能只依赖纯函数测试。
- 不增加模型调用、外部元数据依赖或 Provider 可用性前提；本地唱片库、任务和恢复能力在这些依赖缺席时仍须成立。

## Technical Decisions

- Web Shell 只能通过版本化 API 读取唱片、任务和生命周期事实；Web 不挂载 Music，也不直接读取 NAS 路径。现有 recommendations 与 lifecycle API 不因界面收敛而删除。
- 底层生命周期账本和写入边界保持不变；面向用户使用“最近删除”“移到最近删除”“恢复到原位置”，内部“隔离区”术语不得成为页面标题或一级动作。
- `/quarantine` 可暂时保留为受保护的深链接以兼容既有恢复能力，但必须从一级导航移除，并由任务页文件操作区域提供新的可达入口。
- 高风险文件操作继续遵循 Plan → 预览 → 明确确认 → 幂等执行 → 审计 → 可恢复；WATCH_ONLY Root 始终禁止写入、改名、移动、覆盖、删除及权限修改，只有明确授权的 MANAGED Root 可按既有合同执行受控操作。
- 当前冻结架构合同仍记录旧默认入口与侧栏设计；实施 Library First 前必须新增明确的合同版本或批准的变更记录，保留历史 frozen intent，不得静默改写。

## UX & Interaction Patterns

- 产品外壳以唱片库为默认焦点，不得在跳转前闪现今日推荐、找歌或隔离区内容。
- Album 详情继续优先呈现封面、标题、艺术家、年份、音频规格、简介、主要操作和曲目；revision、模型名、哈希、稳定 ID、来源路径和完整发行证据继续折叠在渐进式“管理唱片”区域。
- 从生命周期结果进入最近删除时，应定位到对应计划或结果；返回任务页时保留原任务上下文。完整性风险和角色允许的下一步不能因导航收敛而隐藏。

## Cross-Story Dependencies

- 默认入口与导航收敛必须和最近删除的新入口同时成立：移除“隔离区”一级入口前，任务页及生命周期结果必须已提供可验证的查询、审计和恢复路径。
- 两个 Story 都依赖现有 M1.3 生命周期、鉴权和任务账本合同；它们只改变入口、路由与用户语言，不改变账本语义或扩大文件操作权限。
