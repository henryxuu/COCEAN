# COCEAN M1.3：唱片生命周期与安全删除

## Why

COCEAN 已能治理唱片身份、字段、封面和详情体验，但用户仍无法安全地隐藏不想看到的唱片、隔离错误本地版本或恢复误操作。直接增加“删除专辑”会混淆聚合 Album、LocalVersion、NAS 源文件和播放器副本，并带来不可恢复的数据损失。M1.3 要在不放宽现有 Music 只读边界的前提下，建立可预览、可确认、可审计、可恢复的生命周期闭环。

## Capabilities

- **CAP-1 唱片显示状态**
  - **intent:** 管理员可以隐藏或恢复一张唱片，以整理日常唱片库而不改变任何源文件。
  - **success:** 隐藏项默认不出现在唱片库与搜索结果中，可在管理视图找回；重扫、身份治理和服务重启均不改变人工状态。

- **CAP-2 隔离计划预览**
  - **intent:** 管理员可以在移动文件前查看一个本地版本的完整隔离计划和影响。
  - **success:** 预览列出冻结的 Root、LocalVersion、文件相对路径、大小、校验身份、目标位置、预计空间、活动任务和全部阻塞原因，且创建预览不会改变文件或曲库状态。

- **CAP-3 安全隔离**
  - **intent:** 管理员可以确认有效计划，将一个 MANAGED Root 中的单个 LocalVersion 移入 COCEAN 隔离区。
  - **success:** 只有计划中全部成员均通过执行前复验后才进入成功状态；WATCH_ONLY、只读挂载、证据漂移、边界逃逸或活动任务均明确拒绝，任何部分执行都不得显示成功。

- **CAP-4 可恢复操作**
  - **intent:** 管理员可以依据原隔离清单把一个隔离版本恢复到原位置。
  - **success:** 原路径全部可用且身份一致时完整恢复；路径占用、Root 政策变化、隔离文件缺失或哈希异常时不覆盖现有文件，并返回可操作的冲突状态。

- **CAP-5 审计与故障恢复**
  - **intent:** 系统可以追踪生命周期命令并在重试、崩溃或并发请求中保持真实状态。
  - **success:** 隐藏、恢复、计划、确认、逐文件执行、失败和取消均关联 actor、requestId、revision 与不可变事件；重复请求结果一致，进程重启能从逐文件证据继续或进入 `RECOVERY_REQUIRED`。

- **CAP-6 面向用户的生命周期界面**
  - **intent:** 用户可以从唱片详情和独立隔离区理解当前状态并执行其角色允许的下一步。
  - **success:** UI 使用“从唱片库隐藏”“移入隔离区”“恢复到原位置”等用户语言，显示对象、空间、时间、影响、失败原因和恢复入口；MEMBER 只读，匿名不获得路径、actor 或历史。

## Constraints

- `WATCH_ONLY` 永远不得改名、移动、覆盖、删除或写入；扫描动作在所有 Root 上仍然只读。
- 只有部署时明确声明为 `MANAGED`、以读写方式挂载且通过运行时权限探针的 Root 才能执行隔离或恢复；现有 FNOS Music Root 不自动改策略或挂载。
- 隔离目标是一个 Root 中的一个 `LocalVersion`；聚合 Album 的多个版本不得由一个模糊动作批量处理。
- 计划冻结 Root、版本 revision、相对路径、大小和 SHA-256；执行前必须逐项复验，并拒绝符号链接逃逸、根边界逃逸、特殊文件和事实漂移。
- 隔离目录必须位于 Music Root 之外并由 COCEAN 独立管理；目标非空、身份不明或哈希不符时失败关闭，绝不覆盖。
- 涉及目标文件的活动扫描或未完成投送任务阻止隔离；历史与已完成播放器副本只提示影响，不自动删除或修改。
- 多文件失败必须保留逐项结果与补偿证据，进入诚实的失败或恢复状态；不得回滚审计历史或宣称原子文件系统能力。
- 隔离成功或恢复成功后，只能通过现有互斥与快照规则触发增量对账；治理记录、身份历史和投送历史不得丢失。
- 只有 ADMIN 可以改变生命周期状态；MEMBER 只读，匿名不得读取隔离清单、私人路径、actor、requestId 或事件历史。
- 所有真实 FNOS 隔离/恢复验收必须另行授权，并首先使用独立 MANAGED QA Root；不得以现有 Music 主库作为首次写操作样本。

## Non-goals

- 永久删除、自动过期清理或绕过隔离区的删除入口。
- 文件夹/文件改名、跨 Root 移动、sidecar 写入或嵌入音频标签写回。
- 自动删除、移动或重建播放器中的既有副本。
- 跨 Root、跨版本或整库批量隔离。
- 依赖大模型判断删除对象、冲突或恢复路径。

## Success signal

在独立 MANAGED QA Root 中，管理员预览并确认隔离一个测试 LocalVersion：精确文件进入隔离区、唱片状态与任务账本一致、Music 主库和设备副本不变；随后按原清单完整恢复，扫描后 Album ID、字段、封面和版本关系保持。对同一场景改为 WATCH_ONLY、制造目标冲突或中断 Worker 时，系统分别拒绝、保留现有文件或进入可恢复状态，且未经确认的永久删除始终为零。

## Assumptions

- M1.3 隔离文件无限期保留；保留期、容量治理与永久清理以后续独立规格决定。
- 首版一次计划只覆盖一个 Root 中的一个 LocalVersion。
