topic: COCEAN 曲目级安全删除
updated: 2026-08-16T20:14
---

- (direction) 用户要求为下一阶段定义可直接实施的曲目级删除规格，但当前 M1.3.1 不实现端点、按钮或文件写入。
- (capability) CAP-1 管理员可按 Album/LocalVersion/Track 选择单个数字音频资产并生成只读影响预览；成功标准是预览列出冻结源身份、文件数、字节、版本/Album 影响与阻断项。
- (capability) CAP-2 管理员可对明确 MANAGED Root 的可分割单文件曲目确认可恢复移动；成功标准是全单哈希复验后原子执行、无覆盖、账本可审计且默认不永久删除。
- (capability) CAP-3 管理员可从最近删除按原始路径恢复曲目；成功标准是目标空闲且源身份一致时恢复，任何冲突或漂移都失败关闭且不部分覆盖。
- (capability) CAP-4 系统在移动或恢复后增量重建受影响 LocalVersion 与 Album；成功标准是曲数、碟号、主版本、封面引用、完整性问题、排序与投送事实一致且治理历史不丢失。
- (capability) CAP-5 ADMIN 可执行，MEMBER 只读脱敏概要，匿名无数据；成功标准是 API/UI/审计均不泄露 actor、绝对路径、哈希或内部证据。
- (constraint) WATCH_ONLY Root 永远禁止移动、删除、改名、写标签、chmod/chown；预览必须返回稳定阻断而非伪成功。
- (constraint) Plan→预览→明确确认→幂等执行→不可变审计→可恢复；预览后源、目录、符号链接、权限、目标占用或 revision 漂移时全单失败关闭。
- (constraint) CUE+整轨镜像、共享物理文件或无法一对一归属的资产不得按逻辑曲目拆删，返回 UNSPLITTABLE_ASSET。
- (constraint) 删除最后一个可播放音频文件不得产生零曲目幽灵 Album，应阻断并引导使用 Album 级最近删除。
- (constraint) 只移动目标音频及能被唯一归属的曲目级 companion；封面、cue、log 等 Album 共享附件不随单曲移动。
- (constraint) 同一曲目的其他 LocalVersion、实体版本和 DeliveryCopy 不被级联删除；当前主版本失效时按确定性规则重选，否则标记治理问题。
- (constraint) 执行必须冻结 root、relative path、size、mtime、SHA-256、media file ID、Album/LocalVersion revision 与目标相对路径；Worker 只能消费冻结证据。
- (decision) 数据库采用独立 TrackLifecyclePlan/Item append-only 账本并以 requestId 精确幂等；既有 Album lifecycle 账本不改写。
- (decision) 错误码至少覆盖 WATCH_ONLY_ROOT、LAST_PLAYABLE_TRACK、UNSPLITTABLE_ASSET、SOURCE_DRIFT、TARGET_CONFLICT、SYMLINK_BOUNDARY、ACTIVE_SCAN、ACTIVE_DELIVERY、REVISION_CONFLICT。
- (assumption) 默认把 Track 删除解释为从一个数字 LocalVersion 移走其唯一音频资产，不删除音乐作品抽象、实体收藏或其他版本。
- (note) 实现范围需覆盖 contracts、schema migration、database、server、worker、web、权限、审计、恢复、单元/集成和独立 MANAGED QA；生产 Music 与 SP3000M 不作为写入验收对象。
- (event) Coherence PASS：五项能力均有可测试成功条件，约束明确排除 WATCH_ONLY、不可分割资产、最后可播放曲目与永久删除。
- (event) Preservation PASS：Epic 4.1 的领域边界、预览确认、冻结证据、恢复、Album 重建、权限、QA 与当前阶段不实现要求均已保留；wrapper-only 内容无。
- (event) Spec finalized：SPEC.md、state-machines.md 与 verification-matrix.md 已由 memlog 再派生，无开放问题，可供下游实施。
